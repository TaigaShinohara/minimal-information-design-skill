# 置換・分割・段階表示のパターン集

SKILL.md の原則3・4・6を場面別に当てはめるための型。新しい型を発明する前に、ここから選ぶ。

## 1. 文字からの置換パターン

- 状態の説明文 → 色と形の変化＋アイコン1つ。例：完了は色の変化とチェックの形で示し、完了しましたの文は視覚上は置かない。ただし状態変化はアクセシブルネームや通知など非視覚的な手段でも同じ内容を伝える。
- 数量の説明文 → バー、ドット、ゲージで量を示し、数値は必要な場合だけ小さく添える。
- 割合や比較 → 面積、長さ、位置で示す。文章での比較説明は置かない。
- 場所の説明 → 地図上の点と距離の短い表記。住所の文章は詳細へ。
- 手順の説明文 → ステップ表示と今の位置の強調。手順そのものをUIの順序で示す。
- 注意文の常時表示 → 起きたときにだけ出す後出し表示へ変える。常時置く注意は読まれない。
- 項目の説明文 → 代表画像やプレビューへ置き換える。画像で伝わらない項目だけ短いラベルを残す。
- 空状態の長い説明 → 状態を表す図形1つ＋次に押すボタン1つ。説明文は置かないか1行まで。

## 2. 分割と折りたたみのパターン

- 設定が多い → よく使う少数だけを出し、残りは設定の詳細ページへ集約する。
- 詳細情報が多い → 一覧では要約（図形＋短いラベル）だけ、詳細はタップ先の専用ページへ。
- 入力が長い → ステップに分ける。各ステップは1目的だけにし、進捗はドットやバーで示す。
- 似た項目が多い → グループ化し、グループ見出しだけを先に見せる。中身は折りたたむ。
- 履歴や過去分 → 初期表示は最新だけにし、過去は別の場所（履歴）へまとめる。
- 補助機能が主画面を圧迫する → メニューや下部の補助導線へ移し、主画面は主目的だけにする。

## 3. 並び順のパターン

正本は SKILL.md の原則8。ここは当てはめの要約であり、条件が食い違ったら原則8を優先する。

- 読む情報：重要度順に上から下、同一行では左から右。
- 主要ボタン（片手タッチ操作のモバイルのみ）：画面下部に固定。最も頻繁な操作1つは右下を優先する。左手持ち・右から左へ読む言語では左右反転を許す。
- 主要ボタン（デスクトップ／Web）：親指ルールは使わない。読み順の末尾とプラットフォームの慣習位置を優先し、フォーカス順を読み順・重要度順と一致させる。
- 補助ボタン：主要ボタンの近くで、主要ボタンより目立たせない。
- 危険な操作：押しやすい場所／目立つ位置から外し、主要ボタンと離す。色でも主要ボタンと競合させない。
- リスト：重要度か利用頻度の高い順を既定とし、並び替えは必要な場合だけ操作として残す。

## 4. 段階表示（アニメーション）のパターン

- 画面表示時：主役 → 主要ボタン → 補助情報の順に、短い間隔で出す。
- リスト表示時：上から順に出す。順番が重要度の順と一致している場合だけ使う。
- 展開時：開く方向へ広げ、中身は見出しに近いものから出す。
- 結果表示時：結果そのもの → 次のアクション → 詳細の順に出す。詳細は求められたときだけ展開する。
- 削除や追加：対象が縮む／現れる動きで、増減が追えるようにする。

どのパターンでも、動きが終わった最終状態だけで内容が伝わることを前提にする。動きの途中でしか伝わらない情報は置かない。OSの「動きを減らす」設定がある場合は段階表示をやめ、最終状態を即時に出す。

## 5. 切り捨ての典型例

- 誰も使わない統計や参考数値の常時表示
- 見出しと同じ内容を繰り返す説明文
- 念のために置いた注意書き、免責寄りの常時表示
- 飾りの画像、意味のないバッジ、視覚上で二重に同じことを言うアイコンとラベルの組（ただし見えるラベルを消す場合でも、スクリーンリーダー向けの読み上げ名・アクセシブルネームは残す。読み上げ名は重複ではなく情報である）
- ほとんどの人が変えない設定項目の常時表示（既定値＋設定ページへ）
- 古いお知らせや終了した機能への導線
